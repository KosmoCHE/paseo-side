Type `/side` in a Claude Code agent's composer to fork the conversation into a side agent that sees the main agent's history. The side agent is named `side: <main agent's name> · <topic>`, the topic being the first 20 characters of the first line of its first message: the message after `/side` when there is one, otherwise your first message, added once that turn ends (slash commands don't count, and a name you give the side agent in the meantime stays). In Claude Code's own session list, the session keeps the name the side agent was opened with. The main agent is not affected and sees only the messages the side agent sends it. Without a message after `/side`, the side agent waits for you.

The side agent is a subagent of the main agent. It does not open by itself: it appears in the subagent list above the main agent's composer and opens when you click it. To open it on the right, set Settings → Open location → "Clicking a subagent in an agent chat" to On the side. When the main agent is archived, its side agents that are not open are archived with it, and open ones are detached and stay. "Archive finished subagents" in the subagent list also archives idle side agents.

The side agent's rules follow Codex's `/side`. A hidden note after the inherited history tells the model that everything before it is reference only, not a task to continue. In the side conversation it answers questions and looks around without changing anything, stays away from subagents and background tasks, and changes files, git state or configuration only when you ask for it there. The note also gives the main agent's Paseo ID, so the side agent can message the main agent with the paseo skill.

You can open a side agent while the main agent is running. It continues from what the main session has written so far. A tool call still running is recorded in the side agent as failed, saying its result stays in the main session, and the side agent ignores notifications about background tasks the main session started.

The side agent is a native fork: the plugin copies the main session's whole Claude Code transcript with a new session ID and imports the copy into Paseo, in the main agent's workspace. The timeline shows the main session's whole history; like the main agent, the model sees only the latest compaction and what follows it. The side agent gets the main agent's directory, model, mode, thinking option and provider options, and no tools are added or removed. Its first request therefore opens exactly like the main session's last one and reads its prompt cache: only the side note and your new message are billed at full price. The cache lasts 5 minutes after the main session's last request by default. Behind a gateway, a request sent to a different account misses it. Claude Code fixes its tool list when its process starts, so a main agent whose process started before Claude Code's tool list changed sends different tools, and the side agent's first request misses the cache.

Only Claude Code agents are supported, including custom providers based on Claude Code, on Paseo 0.17.3 or later. The side agent sends the copied history and your messages to the same provider as the main agent. The plugin reads and writes Claude Code transcripts in the main session's project folder, and connects to the local daemon with the daemon home's `local-credential` to import the copy and set its model, mode and thinking option, which the plugin API does not offer.

Side agents carry the labels `side=<main agent ID>` and `paseo.parent-agent-id=<main agent ID>`. The copied transcript is written to the main session's Claude Code project folder without file-history snapshots, so the side agent cannot undo file changes made before the fork. Each side agent's transcript is a full copy of the main session's.

`/side` with an attachment does not run: Paseo sends the text and the attachment to the main agent as an ordinary message. Send `/side` alone, then send the attachment in the side agent.
